# Data Studio

**一个跑在自己电脑上的数据分析工作台。** 从「拿到一份脏数据」到「得出结论」的完整链路，
全部在一个浏览器页面里完成，数据不出本机。

> 面向的场景：临时拿到一份 Excel/CSV，想快速看看里面有什么问题、画几张图、
> 做几步清洗，然后把清洗逻辑带走 —— 而不是打开 Jupyter 从 `pd.read_csv` 重新写一遍。

---

## 为什么做这个

临时分析一份数据时，重复劳动特别多：

- 想知道有哪些列、缺多少值、有没有异常，得写十几行 pandas
- 日期列读进来是字符串，忘了转就画不出时间趋势
- 同一个城市因为多了个空格被分成两组
- 业务给的字段是 `12㎡`、`3室2厅` 这种，得手动拆
- 清洗代码写完就丢，下次遇到同样的问题还得重写

这个工具把这些固定动作做成界面操作，**每一步同时生成等价的 pandas 代码**，
可以直接复制到自己项目里用。既省事，也不至于用完什么都学不到。

---

## 主要能力

六个面板覆盖一份数据的完整处理链路，另外支持把处理结果落表输出：

| 面板 | 做什么 |
| --- | --- |
| **数据概览** | 自动剖析：行列数、字段类型画像、数据质量评分与问题清单、相关性、缺失分布 |
| **画图分析** | 先选分析目的（比较 / 趋势 / 构成 / 分布 / 相关性…），自动匹配图表；支持多指标、分组、堆叠、双轴组合 |
| **数据清洗** | 22 个算子，按用途分组；常用场景一键套用；每步生成 pandas 代码 |
| **SQL 查询** | 数据集自动注册成 SQLite 表，支持窗口函数 / CTE，内置 7 个分析模板 |
| **两份数据对比** | 对账用：结构差异、行级增删改、数值分布漂移、类别构成变化 |
| **数据明细** | 浏览原始数据；多条件筛选与排序（作用于全量数据）；导出 CSV / Excel / JSON / Markdown |
| **数据输出** | 把数据集或 SQL 结果落表到本地 SQLite 文件或已连接的数据库，支持覆盖 / 追加 |

### 几个值得一提的设计

**先问目的，再选图。** 大多数人不是先想「我要画柱状图」，而是先想「哪个城市卖得最好」。
所以绘图面板第一步是选分析意图（比大小 / 看趋势 / 看构成 / 看分布 / 看关系…），
再由系统挑图表类型。

**算子按「我的数据出了什么问题」分组，而不是按技术分类。**
每个算子都带「什么时候用它」和前后效果示例 —— 因为很多人并不知道
「把 12㎡ 变成 12」在数据清洗里叫「提取数字」。

**清洗逻辑可以带走。** 每次清洗都输出一份完整的、可直接运行的 pandas 脚本：

```python
import re
import pandas as pd

df = pd.read_csv('你的数据源.csv')

# 从文字里抠出数字
df['面积_num'] = df['面积'].astype('string').str.findall(r'[-+]?\d+(?:\.\d+)?') \
    .map(lambda v: v[0] if v else None)
# 子串替换（新值填空字符串 = 删除该片段）
df['面积'] = df['面积'].astype('string').str.replace('㎡', '', regex=False)
df = df.drop(columns=['面积'])
```

## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | FastAPI + Uvicorn | 同步接口跑在线程池，重活儿都是 pandas 在做 |
| 数据处理 | pandas + numpy | |
| SQL 引擎 | **标准库 sqlite3** | 见下方说明 |
| 前端 | 原生 JS，无框架 | 没有构建步骤，改完刷新即生效 |
| 图表 | ECharts（本地引入） | **完全离线可用**，不依赖任何 CDN |
| 导出 | openpyxl | |

### 为什么 SQL 引擎用 sqlite3 而不是 DuckDB

DuckDB 在 OLAP 场景确实更强，但这里的需求是「让用户用 SQL 摸一摸几万行数据」，
标准库 `sqlite3` 已经够用（自带 SQLite 3.5x，窗口函数和 CTE 都支持），
而且**零额外依赖** —— 对整个项目的安装体验影响很大。

安全上是只读的：不靠正则黑名单，而是用 `conn.set_authorizer()` 注册回调，
在 SQLite 解析层拒绝一切写操作和 ATTACH，绕过不掉的。

## 一些实现细节

写代码时踩过的坑，记下来免得下次再踩。

**SQL 标识符不要用字符白名单。**
最初用 `[\w\u4e00-\u9fff]+` 校验表名，结果 Excel 的 sheet 名 `Result 1`（带空格）
直接判成非法，导入失败。SQLite 双引号内其实可以放任意字符，
正确做法是 `'"' + name.replace('"', '""') + '"'`，MySQL 用反引号同理。

**pandas 3.0 的 `DatetimeIndex` 默认精度是微秒，不是纳秒。**
用 `idx.asi8` 取值再 `pd.to_datetime()` 会按纳秒解释，所有日期变成 1970 年，
而且**不报错**。按位置抽索引（`idx[gen.integers(...)]`）最稳。

**`Series.str.findall` 遇到带捕获组的正则会返回 tuple 列表**，不是字符串列表，
`join` 会直接 TypeError。要拿完整匹配加各分组，用 `re.finditer` 自己遍历。

**`Series.replace({...})` 是整值精确匹配**，不是子串替换。
`{'㎡': ''}` 对 `12㎡` 完全不生效 —— 想要 Excel 查找替换的语义要用
`str.replace(pat, repl, regex=False)`。

**图表配色要跟着主题走。**
ECharts 的 option 是后端生成的，颜色如果写死，深色界面下坐标轴文字会糊掉。
用 `contextvars` 把主题传进去，`viz.build(df, spec, theme=...)`，
不用给十几个图表函数都加参数。

**`.bat` 文件必须纯 ASCII。** cmd 解析 `.bat` 用的是启动代码页，
`chcp 65001` 只对后续输出生效、对本文件自身的解析无效 ——
UTF-8 中文会被按 GBK 拆出乱码字节，其中某些恰好是命令分隔符，
把后面整行命令拼错。

## 已知限制

诚实说明，避免误用：

- **数据量**：上传限制 60MB；从数据库导入默认 10 万行、上限 50 万行。
  这是给「临时分析中等规模数据」用的，不是 Spark 的替代品。数据更大请先在
  数据库里聚合再导进来。
- **只有单用户单进程**：数据放在进程内存里，重启就没了（清洗结果可以导出保留）。
  不提供多人协作，这是刻意的 —— 数据分析工具处理的多是敏感数据。
- **只监听 127.0.0.1**：同一局域网的其他电脑也访问不到。
- **exe 版是 PyInstaller 打包的**，里面是字节码。普通用户看不到源码，
  但理论上可以用工具反编译出接近源码的内容。
